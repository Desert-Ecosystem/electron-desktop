# Контрибьютинг в Desert Desktop

Спасибо за интерес к проекту. Здесь рассказывается, как предложить изменение.

Если нужна помощь — создайте issue в GitHub.

## Направления

Вы можете помочь проекту, например:

1. Исправлением багов и улучшением нативной обертки (захват экрана, уведомления, auto-update, splash / кэш).
2. Улучшением документации и локализации.
3. Предложением новой функциональности через issue с описанием сценария.

## Новый код

### Создание issue

Сначала опишите в issue, что хотите изменить, добавить или исправить. Это помогает избежать дублирования работы и упрощает ревью.

1. Создайте issue с понятным описанием проблемы или предложения.
2. Дождитесь ответа мейнтейнера. Если предложение принято — переходите к коду.

### Форк

Форк создает личную копию репозитория под вашим GitHub-аккаунтом. Это позволяет вносить изменения, не затрагивая основной проект. Откройте страницу репозитория на GitHub и нажмите кнопку Fork в правом верхнем углу.

### Клонирование форка

```bash
cd ~/projects # Или директория, где хотите держать код
git clone https://github.com/{your-name}/desert-desktop.git
# Не забудьте заменить {your-name} на ваш GitHub username
cd desert-desktop
```

### Сборка

Требования: Node.js LTS, pnpm.

```bash
pnpm install
pnpm dev # dev-режим
```

Сборка под платформы:

```bash
pnpm build:win # Windows x64
pnpm build:mac # macOS arm64
pnpm build:linux # Linux x64
```

### Форматирование и проверки

Перед отправкой PR прогоните локально:

```bash
pnpm typecheck
pnpm lint
pnpm format
```

Код должен проходить `typecheck` и `lint` без ошибок и быть отформатирован через prettier (`pnpm format`).

## Low-effort контрибьюции

Мы ценим любой интерес к проекту, но low-effort PR могут быть закрыты.

Примеры low-effort:

- Исправление одной опечатки.
- Переформулировка одной строки без смыслового изменения.
- Минорные однострочники, не влияющие на логику и поведение.

В таких случаях обычно достаточно issue — мейнтейнеры сами внесут мелочь вместе с более крупными изменениями.

## Как открыть PR?

Все коммиты должны быть названы в соответствии с [Conventional Commits](https://www.conventionalcommits.org/).

```bash
# Добавьте изменения в staging
git add .

# Закоммитьте по Conventional Commits: <type>(<scope>): <описание>
# типы: feat, fix, docs, style, refactor, perf, test, build, ci, chore, revert
git commit -m "feat(picker): добавить выбор экрана со звуком"

# Запушьте в свой форк
git push origin your-branch-name
```

Затем откройте GitHub, перейдите в свой форк и нажмите Create pull request. Заполните описание и отправьте PR. Если в PR нужны правки — открывайте его как draft.
